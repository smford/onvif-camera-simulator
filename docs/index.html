# Install via Homebrew Tap
$ brew tap smford/tap
$ brew install onvif-camera-simulator

# Run interactive TUI simulator
$ onvif-camera-simulator

# Or run 4 cameras headless in background
$ onvif-camera-simulator --no-tui --fleet 4

Architected for NVR Stress Testing

Everything needed to test streaming reliability, auto-discovery, PTZ movement, and AI event ingest under realistic conditions.

🎥

Pure Go Dual RTSP

Built directly on gortsplib/v4 and mediacommon. Emits synchronized 1080p Main and 360p Sub H.264 video with Constrained Baseline Profiles (profile-level-id=42e01f) for instant browser/WebRTC playback.

🕹️

Virtual PTZ Kinematics

Real-time 20Hz continuous and absolute move motor simulation with acceleration clamping, velocity timeouts, and persistent preset coordination.

🔔

WS-BaseNotification Events

Pull-point event queue delivering cell motion (Profile S), AI person detection with normalized bounding boxes (Profile T/M), and vehicle detection to subscribed NVRs.

⚡

SRE Chaos Engineering

Simulate production camera faults on-demand: stream freeze (holding RTSP TCP sockets without packet emission), connection drop / hardware reboot, and packet loss.

🌐

WS-Discovery Multicast

Automatic device discovery on 239.255.255.250:3702 with Probe, ProbeMatch, Hello, and Bye notifications across single and fleet camera topologies.

📊

Interactive TUI & Observability

Full Charm Bubble Tea dashboard with live telemetry, form config tuning, event log ring buffer, and Prometheus /metrics scraping.

Configuration & REST APIs

Flexible configuration and programmatic control for automated integration testing.

# docker-compose.yml services: onvif-simulator: image: ghcr.io/smford/onvif-camera-simulator:latest network_mode: host restart: unless-stopped command: ["--no-tui", "--config", "/app/config.yaml"] volumes: - ./config.yaml:/app/config.yaml:ro
# Launch a fleet of 8 simulated cameras $ onvif-camera-simulator --fleet 8 --no-tui # Each camera is cleanly namespaced across shared ports: RTSP Stream 0: rtsp://127.0.0.1:8554/live/cam0/main RTSP Stream 1: rtsp://127.0.0.1:8554/live/cam1/main ONVIF Service: http://127.0.0.1:8000/onvif/cam0/device_service Dynamic JPEG: http://127.0.0.1:8000/onvif/cam0/snapshot
# Trigger Cell Motion event via REST $ curl -X POST http://127.0.0.1:8000/api/events/trigger \ -H "Content-Type: application/json" \ -d '{"topic":"motion", "state":true}' # Inject 10s Simulated Reboot Chaos $ curl -X POST http://127.0.0.1:8000/api/chaos/inject \ -H "Content-Type: application/json" \ -d '{"type":"reboot", "duration":"10s"}' # Query active cameras and status $ curl http://127.0.0.1:8000/api/cameras
# ONVIF SOAP 1.2 Endpoints: Device Service: http://127.0.0.1:8000/onvif/device_service Media Service: http://127.0.0.1:8000/onvif/media_service PTZ Service: http://127.0.0.1:8000/onvif/ptz_service Event Service: http://127.0.0.1:8000/onvif/event_service Dynamic JPEG: http://127.0.0.1:8000/onvif/snapshot Health Check: http://127.0.0.1:8000/healthz Prometheus: http://127.0.0.1:8000/metrics
