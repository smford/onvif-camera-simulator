Cross-Platform Installation

Native pre-compiled packages and container images available for macOS, Linux, Windows, and Docker.

Install on macOS (Apple Silicon & Intel)

The easiest way to install and stay updated on macOS is via Homebrew Tap.

Homebrew Installation 
# Add tap and install simulator formula
$ brew tap smford/tap
$ brew install onvif-camera-simulator

# Run interactive TUI simulator
$ onvif-camera-simulator --config config.yaml

Apple Silicon (M1/M2/M3/M4)

Direct binary tarball for ARM64 architecture:

$ curl -LO https://github.com/smford/onvif-camera-simulator/releases/download/v0.2.0/onvif-camera-simulator_0.2.0_darwin_arm64.tar.gz
$ tar -xzf onvif-camera-simulator_0.2.0_darwin_arm64.tar.gz

Systemd Daemon Management

Native packages automatically install a secure sandboxed systemd service (/lib/systemd/system/onvif-camera-simulator.service):

# Enable and start camera simulator daemon
$ sudo systemctl daemon-reload
$ sudo systemctl enable --now onvif-camera-simulator

# Inspect service status and follow logs
$ sudo systemctl status onvif-camera-simulator
$ sudo journalctl -u onvif-camera-simulator -f

Install on Windows (x86_64 & ARM64)

Standalone executable with full interactive TUI support inside Windows Terminal or PowerShell.

PowerShell Quickstart
# Download and extract the latest Windows 64-bit release
PS> Invoke-WebRequest -Uri "https://github.com/smford/onvif-camera-simulator/releases/download/v0.2.0/onvif-camera-simulator_0.2.0_windows_amd64.zip" -OutFile "simulator.zip"
PS> Expand-Archive simulator.zip -DestinationPath "C:\Tools\onvif-simulator"
PS> cd "C:\Tools\onvif-simulator"

# Launch simulator in interactive TUI mode
PS> .\simulator.exe --config config.yaml

# Or run headless with 4 simulated cameras
PS> .\simulator.exe --no-tui --fleet 4

Docker & Container Deployments

Multi-architecture images published to GitHub Container Registry (ghcr.io) for linux/amd64 and linux/arm64.

Docker CLI (Host Networking Mode)
# Run container with host network mode for UDP WS-Discovery broadcast
$ docker run -d \
    --name onvif-simulator \
    --network host \
    --restart unless-stopped \
    -v "$(pwd)/config.yaml:/app/config.yaml:ro" \
    ghcr.io/smford/onvif-camera-simulator:v0.2.0 --no-tui
docker-compose.yml
services:
  onvif-simulator:
    image: ghcr.io/smford/onvif-camera-simulator:v0.2.0
    network_mode: host
    restart: unless-stopped
    command: ["--no-tui", "--fleet", "4"]
    volumes:
      - ./config.yaml:/app/config.yaml:ro

Build from Source

Requires Go 1.23 or newer. Zero external dependencies or Cgo required.

Go Install & Git Clone
# Option 1: Install directly with 'go install'
$ go install github.com/smford/onvif-camera-simulator/cmd/simulator@latest

$ cd onvif-camera-simulator
$ make build
$ ./bin/simulator --version

Frigate NVR & go2rtc Configuration

Frigate connects to the high-res 1080p stream for recording and uses the lightweight 360p sub-stream for AI object detection:

frigate/config.yml
mqtt:
  enabled: false

cameras:
  simulator_cam0:
    ffmpeg:
      inputs:
        # High-res 1080p stream for continuous recording
        - path: rtsp://127.0.0.1:8554/live/cam0/main
          roles:
            - record
        # Low-res 360p stream for motion & AI object detection
        - path: rtsp://127.0.0.1:8554/live/cam0/sub
          roles:
            - detect
    detect:
      width: 640
      height: 360
      fps: 10
    record:
      enabled: true
    onvif:
      host: 127.0.0.1
      port: 8000
      user: admin
      password: admin

go2rtc:
  streams:
    cam0_webrtc:
      - rtsp://127.0.0.1:8554/live/cam0/main

Test the RTSP streams directly in your terminal with ffplay or vlc:

# Play Main Stream (1080p20)
$ ffplay -rtsp_transport tcp rtsp://127.0.0.1:8554/live/cam0/main

# Play Sub Stream (360p10)
$ ffplay -rtsp_transport tcp rtsp://127.0.0.1:8554/live/cam0/sub

SRE Chaos Engineering Suite

Trigger realistic camera failures programmatically to verify how your monitoring, alerting, and NVR failover pipelines react:

REST API Fault Injection Examples
# 1. Inject a 5-second RTSP stream freeze (holds TCP connection without sending RTP packets)
$ curl -X POST http://127.0.0.1:8000/api/chaos/inject \
    -H "Content-Type: application/json" \
    -d '{"type":"freeze", "duration":"5s", "camera":"cam0"}'

# 2. Simulate hardware reboot (closes connections, rejects reconnections for 15s)
$ curl -X POST http://127.0.0.1:8000/api/chaos/inject \
    -H "Content-Type: application/json" \
    -d '{"type":"reboot", "duration":"15s", "camera":"cam0"}'

# 3. Simulate flaky network: 30% artificial packet loss for 20 seconds
$ curl -X POST http://127.0.0.1:8000/api/chaos/inject \
    -H "Content-Type: application/json" \
    -d '{"type":"packet_loss", "percentage":30, "duration":"20s", "camera":"cam0"}'

# 4. Clear active chaos conditions immediately
$ curl -X POST http://127.0.0.1:8000/api/chaos/clear

REST APIs & ONVIF Endpoints

Programmatic control for CI/CD test automation and observability scraping.

🌐

HTTP REST Endpoints

Control events and inspect status via standard JSON REST calls:

  • GET /api/status • General telemetry & fleet health
  • GET /api/cameras • List active cameras & mounts
  • GET /api/logs • Ring buffer log entries
  • POST /api/events/trigger • Fire motion/AI events
  • POST /api/chaos/inject • Trigger fault injection
  • POST /api/chaos/clear • Restore healthy streaming
📹

ONVIF SOAP 1.2 Services

Full ONVIF standard Profile S, T, and M compatibility:

  • /onvif/device_service • Device capabilities & reboot
  • /onvif/media_service • Profiles & stream URIs
  • /onvif/ptz_service • ContinuousMove & presets
  • /onvif/event_service • WS-BaseNotification
  • /onvif/snapshot • Dynamic JPEG frame generator
📊

Health & Prometheus Metrics

Zero-configuration observability for Kubernetes and Prometheus:

  • GET /healthz • Readiness & liveness probe
  • GET /metrics • Prometheus metrics:
    • simulator_rtsp_clients_active
    • simulator_stream_bitrate_kbps
    • simulator_events_triggered_total
    • simulator_chaos_active
